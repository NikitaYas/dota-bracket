# Турнирная сетка Dota 2

Статический сайт с турнирной сеткой на 24 участника (поддерживается от 2 до 64) для GitHub Pages.
Без сборки и фреймворков: чистые HTML, CSS и ES-модули.

**Адрес сайта:** https://nikitayas.github.io/dota-bracket/
**Репозиторий:** https://github.com/NikitaYas/dota-bracket (ветка `main`)

## Возможности

- **Двойное выбывание** (по умолчанию) с верхней и нижней сеткой, гранд-финалом и перезапуском финала,
  или **одиночное выбывание** с матчем за 3-е место.
- 24 участника → сетка на 32 места: посевы 1–8 проходят первый раунд автоматически (BYE).
- Зрителям видно: сетку с линиями, счёт, победителей, чемпиона, вкладку «Участники» со статусом
  (в игре / выбыл / чемпион) и местами. Наведение на участника подсвечивает весь его путь.
- Масштаб (+ / − / вписать), перетаскивание сетки мышью, на телефоне — прокрутка пальцем.
- Автообновление каждую минуту, пока вкладка открыта.

## Режим администратора

Откройте сайт и нажмите **«Админ»** в правом верхнем углу (или откройте адрес с `#admin` на конце).

- **Клик по участнику** в матче — он победил. Повторный клик по другому участнику меняет победителя.
- **Перетаскивание** (мышью или пальцем):
  - участника из 1-го раунда на любой другой слот 1-го раунда (в том числе BYE) — поменять их местами;
  - участника в следующий матч или на зону «Победа» справа от карточки — отметить победу.
- **Счёт**: два поля справа в карточке матча. Если ввести счёт, победитель выставится автоматически.
- **«сбросить»** над карточкой — отменить результат матча.
- Если изменение затрагивает уже сыгранные дальше матчи, сайт спросит подтверждение и сбросит их.
- **Отменить / Повторить**: кнопки или Ctrl+Z / Ctrl+Y. Ctrl+S — сохранить.
- **Настройки**: название, формат, матч за 3-е место, перезапуск гранд-финала, BO1/BO3/BO5 по раундам,
  «Перемешать посев», «Посев по списку», «Сбросить все результаты», список участников
  (переименовать, добавить, удалить, вставить список целиком).
- **Экспорт JSON / Импорт JSON** — резервная копия сетки в файл и загрузка из файла.
- Несохранённые изменения автоматически хранятся как черновик в браузере; при следующем входе сайт
  предложит «Восстановить черновик».
- **«Сохранить»** публикует сетку в репозиторий (файл `data/bracket.json`) — для этого нужен токен.

### Как создать токен GitHub (один раз)

1. Войдите на GitHub под аккаунтом **NikitaYas**.
2. Откройте https://github.com/settings/personal-access-tokens/new
   (Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token).
3. Заполните:
   - **Token name**: например, `dota-bracket admin`;
   - **Expiration**: срок действия (например, 90 дней — потом создайте новый);
   - **Resource owner**: `NikitaYas`;
   - **Repository access**: *Only select repositories* → выберите **dota-bracket**;
   - **Permissions → Repository permissions → Contents**: **Read and write**
     (Metadata: Read-only выставится автоматически).
4. Нажмите **Generate token** и скопируйте токен (начинается с `github_pat_…`).
5. На сайте: «Админ» → вставьте токен → «Войти». Галочка «Запомнить на этом устройстве» сохраняет
   токен в браузере; без неё он забудется при закрытии вкладки. Кнопка «Выйти» удаляет токен.

Токен хранится только в вашем браузере и отправляется только на `api.github.com`.
**Никогда не добавляйте токен в файлы репозитория.** Если токен утёк — удалите его на той же странице GitHub.

Без токена можно нажать «Без токена»: редактировать сетку и экспортировать JSON, но не публиковать.

### Когда изменения увидят зрители

У GitHub API без токена лимит — **60 запросов в час на один IP-адрес**, и он общий для всех вкладок
и всех зрителей за одним роутером (например, Wi-Fi на LAN-турнире). Ответы «не изменилось» (304)
без токена тоже расходуют лимит. Поэтому сайт:

- при открытии страницы читает данные через GitHub API (свежая версия сразу после «Сохранить»);
- автообновляется каждую минуту из файла `data/bracket.json` на GitHub Pages (без лимитов; файл
  обновляется примерно через 1 минуту после сохранения), а через API — не чаще раза в 5 минут;
- следит за остатком лимита (`X-RateLimit-Remaining`): когда остаётся 5 запросов или меньше, API
  откладывается до сброса лимита, и эта отметка общая для всех вкладок браузера.

Итого зрители видят изменения в течение 1–2 минут после сохранения. Более старая версия с GitHub Pages
никогда не заменяет уже показанную более новую. Админ с токеном всегда читает через API
(лимит 5000 запросов в час), поэтому при входе в режим админа сайт перечитывает актуальные данные.

## Публикация на GitHub Pages (один раз)

1. Создайте публичный репозиторий **NikitaYas/dota-bracket** и загрузите туда все файлы этой папки
   в ветку `main`.
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/ (root)` → Save.
3. Через 1–2 минуты сайт будет доступен по адресу https://nikitayas.github.io/dota-bracket/

Файл `.nojekyll` отключает обработку Jekyll, чтобы GitHub Pages отдавал файлы как есть.

## Ручное редактирование данных

Все данные — в `data/bracket.json`:

```json
{
  "version": 1,
  "title": "Dota 2 Турнир",
  "format": "double",
  "thirdPlace": true,
  "grandFinalReset": true,
  "participants": [{ "id": "p1", "name": "Участник 1" }],
  "slots": ["p1", null, "p16", "p17"],
  "results": { "W1-2": { "winner": 0, "score": [2, 1], "p": ["p16", "p17"] } },
  "bestOf": { "W1": 1, "GF": 5 },
  "updatedAt": "2026-10-22T12:00:00.000Z"
}
```

- `format`: `"double"` (двойное выбывание) или `"single"` (одиночное).
- `slots`: позиции первого раунда (32 для 24 участников), `null` — BYE.
  Пары: слоты 0–1, 2–3, … По умолчанию стандартный посев 1–32, 16–17, 8–25, 9–24, …
- `results`: ключ — id матча (`W1-3` — верхняя сетка, 1-й раунд, 3-й матч; `L2-1` — нижняя сетка;
  `GF1`, `GF2` — гранд-финал и перезапуск; `3RD` — матч за 3-е место). `winner`: 0 — верхний участник
  карточки, 1 — нижний. `p` — id участников матча (если участники изменились, результат сбрасывается;
  при ручном редактировании `p` можно не писать — сайт подставит его сам, если матч готов).
- `bestOf`: формат матчей по раундам (`W1`…, `L1`…, `GF`, `3RD`) — 1, 3 или 5. Только для отображения.

Испорченные или неполные данные не ломают сайт: неизвестные и некорректные поля игнорируются
(отбрасывается только испорченное поле, например один неверный результат), недостающие получают
значения по умолчанию. Если файл вообще не является JSON, сайт покажет ошибку загрузки, а при попытке
сохранить из режима админа предупредит, что перезапишет данные на GitHub.

## Структура

| Файл | Назначение |
| --- | --- |
| `index.html` | Страница |
| `css/style.css` | Стили |
| `js/engine.js` | Логика сетки (без DOM, работает и в Node) |
| `js/storage.js` | Загрузка и сохранение (GitHub API + запасной вариант); настройки репозитория — `CONFIG` в начале файла |
| `js/app.js` | Отрисовка и взаимодействие |
| `data/bracket.json` | Данные турнира |
| `tests/engine.test.mjs` | Тесты логики |

## Локальный запуск и тесты

```bash
python -m http.server 8765
# открыть http://localhost:8765/
```

На `localhost` сайт читает локальный `data/bracket.json` (а не GitHub API); добавьте `?api=1`,
чтобы проверить чтение через API.

Тесты (Node 18+):

```bash
node --test tests/
```
